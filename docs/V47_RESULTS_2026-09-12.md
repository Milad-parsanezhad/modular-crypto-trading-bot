### Interpretation of C1

Temperature scaling materially improved probability quality while preserving discrimination. Relative to the paired same-run control, common-space Brier improved from `0.61651` to `0.60222`, mean reliability error improved from `0.02205` to `0.01598`, and macro AUC was effectively preserved (`0.59889` to `0.59989`). Aggregate expectancy and PF also moved slightly in the favorable direction.

However, these improvements did not repair the main robustness problem: only 2 of 5 OOS folds were economically positive, the PF remained below 1.05, the stress PF remained below 1.00, and drawdown exceeded the 5% firewall. Therefore calibration is a real bottleneck, but it is not the only bottleneck.

## Engineering defect and repair record

The initial v0.47 execution (`34704888326`) failed before an admissible scientific decision was produced because the runner required near-bitwise equality between a newly refit C0 model and the historical v0.46 scalar Brier score.

The investigation confirmed identical relevant software versions but different GitHub-hosted runner regions/machines. Logistic-regression floating-point fits can differ slightly across machines. The invalid cross-machine scalar-equality provenance guard was therefore replaced by stronger scientific checks:

- C0/C1/C2 paired within the same canonical run;
- exact canonical v0.46 artifact/run/head verified;
- exact v0.46 fold/symbol evaluation units verified;
- inherited v0.46 scientific source files required to have zero git diff from the canonical v0.46 head;
- regression test proves v0.47 forecast-metric semantics equal v0.46 semantics for identical probabilities and labels;
- numerical drift versus historical v0.46 scalar values recorded transparently as diagnostic metadata.

No arm, threshold, feature, asset, venue, label, cost, Financial Governor rule or promotion gate was changed by this repair.

## Scientific conclusion

v0.47 establishes that simple temperature scaling can substantially reduce the calibration/reliability error identified in v0.45-v0.46, while keeping discrimination intact. Yet the temporal economic instability persists: the calibrated candidate still produces only 2/5 positive folds and still fails stress-profit-factor and drawdown gates.

Therefore the next stage should not add a more expressive calibrator or a larger predictive model. The next research question should isolate **temporal/regime non-stationarity** and determine whether the remaining edge is conditional, episodic, or distribution-shift sensitive.

Any v0.48 experiment must be preceded by a separate research note and prospective preregistration. Kraken remains sealed until a candidate passes all development gates and a dedicated external-holdout protocol is frozen.

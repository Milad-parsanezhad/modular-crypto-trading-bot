This finding does **not** establish that any individual Ichimoku, ICT/SMC, FVG, order-block, or Brooks-inspired component is unprofitable. It establishes only that the frozen v0.39R composite admission rule is too restrictive to yield evaluable sample size in this development window.

## Scientific interpretation

The reconstruction objective succeeded: the original strategy thesis is now represented as one deterministic, documented, auditable architecture rather than being scattered across v0.17–v0.38 modules.

The strict empirical configuration failed for a different reason than v0.38. v0.38 had adequate sample size and average economics but failed temporal persistence/CI gates. v0.39R, by contrast, fails at **admission/sample generation** before profitability can be estimated.

These are distinct failure modes and must not be conflated.

## Anti-overfitting decision

No v0.39R threshold will be lowered after this result.

Specifically, this result does not authorize changing `min_score=6` to 5, disabling CUSUM, or removing a component and rerunning under the same label. Any such change would be a new hypothesis and must be preregistered under a new experiment identifier.

## Next scientifically valid step

Proceed to v0.39 as a separately preregistered learning/process experiment. The preferred direction is **hierarchical/ablation-aware, regime-shift-aware temporal re-estimation** rather than another post-hoc fixed filter:

1. preserve the canonical component definitions from v0.39R;
2. estimate which component subsets are conditionally informative using purged walk-forward development folds only;
3. use embargo and strict causality;
4. test component ablations and interactions without touching Kraken;
5. require the same frozen development robustness gates before any holdout authorization;
6. keep Kraken sealed until a development candidate passes every gate.
